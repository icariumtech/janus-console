# Phase 15-01: Data Directory Audit + Bug Fixes

## Goal

Establish a clean, verified baseline before the data directory restructure begins. Fix known bugs in `data_loader.py`, strip redundant YAML fields, and run alignment audits to document any gaps between the TypeScript types and YAML data.

No structural changes to data files yet — this phase is read-and-fix only.

## Context

The design proposal (`wiggly-beaming-oasis.md`) identified several bugs and redundancies in the current codebase that should be fixed before the restructure begins. Fixing them now prevents carrying broken behavior into the new structure.

Phase 12 (requirements tracking + dead code cleanup) must be complete before this plan executes — Phase 12 may overlap on dead code in `data_loader.py`.

## Tasks

### Task 1: Fix load_location() undefined attribute (data_loader.py:75)

`load_location()` references `self.locations_dir` which is never set in `__init__`. This method would crash if called.

Check if `load_location()` has any call sites:
```bash
grep -n "load_location\b" terminal/data_loader.py terminal/views.py
```

If unused: delete the method entirely.
If used: define `self.locations_dir` in `__init__` pointing to the correct directory.

### Task 2: Remove duplicate return None (data_loader.py:430)

There is a dead `return None` at line 430 after an earlier `return None` at line 428 inside `find_location_by_slug`. Remove the duplicate.

### Task 3: Delete dead load_maps() method

`load_maps()` searches a `maps/` directory (plural) that does not exist anywhere in the codebase. Verify no call sites exist, then delete the method.

```bash
grep -n "load_maps\b" terminal/data_loader.py terminal/views.py
```

### Task 4: Strip has_orbit_map from system_map.yaml files

`views.py` dynamically derives `has_orbit_map` by checking if the orbit map file exists. Any `has_orbit_map:` field in `system_map.yaml` body entries is redundant.

Find all occurrences:
```bash
grep -rn "has_orbit_map" data/galaxy/
```

Remove the field from all YAML body entries found.

### Task 5: Alignment audit

Run these checks and document findings in a comment block at the top of this plan (or in a separate audit note):

1. **TypeScript types vs YAML fields**: Grep `src/types/` for any field names that reference `manifest` — if the ship map response exposes a `manifest` key, frontend may break when it becomes `deckplan`.
   ```bash
   grep -rn "manifest" src/types/
   ```

2. **Manifest references in frontend API calls**: Any frontend code reading a `manifest` key from API responses.
   ```bash
   grep -rn "manifest" src/services/ src/components/
   ```

3. **slug: ship usage**: Confirm `slug: ship` in `data/campaign/ship.yaml` is not read by any code path.
   ```bash
   grep -rn "slug.*ship\|ship.*slug" terminal/data_loader.py terminal/views.py src/
   ```

4. **planets: / stations: fields**: Confirm `planets:` and `stations:` in galaxy `location.yaml` files are not consumed by frontend.
   ```bash
   grep -rn "\.planets\b\|\.stations\b" src/
   ```

5. **total_decks key**: Confirm whether any frontend component reads `total_decks` directly from a manifest object vs from the top-level response.
   ```bash
   grep -rn "total_decks" src/
   ```

### Task 6: Add body_slug validation script

Create a small validation script (or add a management command) that:
1. Scans all location directories in the current data structure
2. Checks any `body_slug` field resolves to a real `data/galaxy/` path
3. Reports mismatches

This script is infrastructure for Phase 18 — it validates the migration before orbital_stations entries are deleted.

Location: `tools/validate_body_slugs.py` or inline in Phase 18 plan execution.
