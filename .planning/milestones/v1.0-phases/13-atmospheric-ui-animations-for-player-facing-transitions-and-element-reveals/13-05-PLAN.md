    1. View-to-view transitions: glitch-out burst → dark frame → fade-in with typewriter boot label

  </what-built>

  <how-to-verify>
Start the dev server: `npm run dev` (or use running server at http://localhost:5173)
Open the player terminal: http://localhost:5173/terminal/

**Scenario 1 — View transitions:**
In the GM Console, switch the active view from STANDBY to ENCOUNTER.
- Expected: Player terminal shows a glitch burst on the outgoing STANDBY view, brief dark frame, then ENCOUNTER fades in clean
- Expected: Center-screen text "TACTICAL DISPLAY INITIALIZING..." appears and typewriters in, then fades out

Switch from ENCOUNTER back to STANDBY.
- Expected: ENCOUNTER view glitches off, brief dark, STANDBY glitches into existence (signal-loss feel)
- Expected: Center-screen text "STANDBY MODE ACTIVE" appears briefly

Switch from STANDBY to BRIDGE.
- Expected: Same glitch-out pattern; "BRIDGE SYSTEMS ONLINE" typewriters in

**Scenario 2 — Bridge tab switching (should NOT glitch):**
While in BRIDGE view, switch between MAP, CREW, LOGS, STATUS tabs.
- Expected: Existing GSAP fade transition only — no glitch burst (bridge tab changes are not view_type changes)

**Scenario 3 — Bridge panel stagger:**
Switch to BRIDGE view (first time or refresh page).
- Expected: Bridge content panels fade-slide in sequentially with ~100ms delay between each
- Expected: Animation plays once then panels remain static

**Scenario 4 — Overlay animations:**
While in BRIDGE or ENCOUNTER view, open the CHARON dialog.
- Expected: Backdrop creeps in as radial vignette from edges. Dialog container flickers in (rapid opacity pulses, ~280ms)
- Expected: No instant appearance; the flicker is visible before dialog is stable

Close the CHARON dialog.
- Expected: Dialog fades out with slight scale reduction (~300ms); NOT an instant disappearance

Open the DocumentDialog (GM sends a document to players).
- Expected: Document panel scans in from top to bottom (clip-path wipe, ~500ms)
- Expected: Backdrop is radial vignette, not uniform black

Open the CommTerminalDialog.
- Expected: Similar top-down scan reveal (~400ms)

**Scenario 5 — Room reveal animations:**
Set active view to ENCOUNTER. In the GM Console encounter panel, hide all rooms then reveal one room.
- Expected: Room flickers briefly (opacity pulses) then becomes solid/visible

Reveal all rooms using REVEAL ALL button.
- Expected: Rooms reveal in a top-to-bottom cascade wave, each offset by ~75ms

Hide all rooms using HIDE ALL button.
- Expected: Rooms flicker out in top-to-bottom cascade order

**Scenario 6 — Token reveal:**
With some rooms hidden: place a token in a hidden room (GM only sees it dimly). Reveal that room.
- Expected: Room flickers in, then ~200ms later the token fades in
- Expected: Other tokens in already-revealed rooms do NOT re-animate

**Scenario 7 — TypeScript build (already automated in Task 1) — confirm no regressions:**
Confirm the app loads without console errors. Check browser console for any React prop warnings or animation-related JS errors.
