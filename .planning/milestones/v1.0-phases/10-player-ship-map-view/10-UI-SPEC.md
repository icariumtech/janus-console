## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` | Main background, map void/canvas background |
| Secondary (30%) | `#0f1515` / `#1a2525` | Panel surfaces, card backgrounds, status panel |
| Accent (10%) | `#4a6b6b` (teal) | Structural borders, wall lines on deck map, active selections, teal headers |
| Interactive accent | `#8b7355` (amber) | Breadcrumb text, active status labels, ONLINE/interactive highlights, CTA labels |
| Destructive | `#8b5555` | CRITICAL system state indicator only |

Source: STYLE_GUIDE.md CSS variables, BridgeView.css, BridgeView.tsx `STATUS_COLORS_GM`.

Accent reserved for:
- Deck map wall rendering (amber `#8b7355` for walls, matching GRID-05 requirement)
- Active/selected room highlight borders
- Breadcrumb text (amber)
- Teal (`#4a6b6b`) for structural panel borders and section header text

Secondary semantic (status colors, read-only — no user action triggers these):
- ONLINE: `#5a7a7a` (teal-dim)
- STRESSED: `#8b7355` (amber)
- DAMAGED: `#8b6a55` (amber-dark)
- CRITICAL: `#8b5555` (burgundy-red) — pulsing animation
- OFFLINE: `#5a5a5a` (muted gray)

Source: BridgeView.tsx `STATUS_COLORS_GM`, StatusSection.tsx.

## Layout Contract

### Player Terminal: SHIP_DASHBOARD view

Primary focal point: `EncounterMapDisplay` (the ship deck map) — largest visual element, occupies the full `flex: 1` area. Status sidebar is a supporting element and must not compete visually with the map.

```
┌─────────────────────────────────────────────────┐
│  TerminalHeader: "SHIP INTERIOR"  52px           │
├──────────────────────────────┬──────────────────┤
│                              │                  │
│   EncounterMapDisplay        │  ShipStatusSide  │
│   (ship deck, read-only)     │  bar (180px)     │
│   fill: 1                    │  - ship name     │
│   tokens: read-only          │  - hull/armor    │
│   room click: no-op          │  - systems list  │
│                              │                  │
│   LevelIndicator (if >1 deck)│                  │
│   anchored bottom-left       │                  │
└──────────────────────────────┴──────────────────┘
```

- Map area: `flex: 1`, `position: relative`, `background: #0a0a0a`
- Status sidebar: `width: 180px`, `background: #0f1515`, `border-left: 1px solid #1f2f2f`
- Sidebar is optional — only rendered if `shipData` is present
- CSS class prefix: `ship-dashboard-view__*` (avoids collision with `.encounter-view` position:fixed)
- The view itself must NOT use `position: fixed` — it renders inside the shared console layout below `TerminalHeader`

### GM BridgeView: right panel replacement

The existing `GmBridgeStatusPanel` (right half of `gm-bridge-content`) is replaced by `GmBridgeShipPanel`:

```
gm-bridge-content (flex row)
├── GmBridgeMapPanel (flex: 1) — unchanged
└── GmBridgeShipPanel (width: 280px, replaces GmBridgeStatusPanel)
    ├── Breadcrumb-style deck selector (if multi-deck)
    ├── EncounterMapDisplay (fill, read-only preview mode)
    │   - no token palette
    │   - room click: toggle reveal (GM can still reveal/hide)
    └── Ship status section (inline toggles, existing pattern)
```

- Width: 280px fixed (same footprint as current `GmBridgeStatusPanel`)
- `background: #0f1515`, `border-left: 1px solid #1f2f2f`

## Interaction Contract

### Player Terminal interactions (ShipDashboardView)

| Interaction | Behavior |
|-------------|----------|
| View load | Map renders immediately from `activeView.location_slug` pointing to ship location |
| Room click | No-op — players cannot toggle room visibility |
| Token hover | Token popup (read-only) — existing `TokenPopup` component, `isGM={false}` path |
| Deck change | `LevelIndicator` buttons switch active deck — local state only, no API call |
| SSE update | Room visibility, door status, token positions update live via existing SSE |

### GM BridgeView interactions (GmBridgeShipPanel)

| Interaction | Behavior |
|-------------|----------|
| Room click | Toggles room reveal/hide — existing `onRoomToggle` API call |
| Deck selector | Switches displayed deck — local state, no API call |
| System status select | Existing `gmConsoleApi.toggleShipSystem()` call — SSE is authoritative |

## Animation Contract

| Element | Animation | Timing |
|---------|-----------|--------|
| View entry | Fade in (opacity 0 → 1) | 300ms, matches existing tab transition timing |
| CRITICAL system | Pulse animation (opacity 0.6 → 1.0) | 1.2s infinite, matches existing `StatusSection.css` pattern |
| Status change | 400ms flicker on changed system row | Matches Phase 2 decision: "400ms flicker" (source: STATE.md line 88) |
| Room reveal | Immediate — no animation | Matches existing `EncounterMapRenderer` behavior |
| Token position | Immediate update on SSE event | No animated movement (source: REQUIREMENTS.md Out of Scope) |
