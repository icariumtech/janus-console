## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between sys-row sub-elements (bar, info text) |
| sm | 8px | Vertical gap between system/resource rows inside panels; panel internal padding |
| md | 16px | Not used inside panels; used for outer layout offsets |
| lg | 24px | Not used in this phase's components |
| xl | 32px | Not used in this phase's components |
| 2xl | 48px | Not used in this phase's components |
| 3xl | 64px | Not used in this phase's components |

Exceptions:
- Panel internal padding: 8px top/bottom, 8px left/right (uses `sm` spacing token — rounded down from mockup's 10px)
- Panel bottom clearance: 128px from bottom (above floating tab bar — existing StatusSection.css value retained)
- Panel top offset: retain existing CSS value — not a spacing token (existing overlay positioning, not subject to token scale)
- Panel width: 138px — layout dimension, exempt from spacing token scale (fixed by approved mockup `sample_ui/status-tab-hybrid.html`)
- Row top margin: 8px between rows (uses `sm` token); hull-row bottom margin: 8px with separator border (rounded down from mockup's 10px)
- Stagger animation delay increment: 80ms between rows (D-13)
- Change-flash duration: 600ms (D-11)
- Condition bar height: 3–4px (terminal readout style — thinner than current 16px)
- Touch target: panels are display-only (`pointer-events: none`), no touch targets inside

Source: CONTEXT.md D-04, D-13; sample_ui/status-tab-hybrid.html; StatusSection.css

## Layout Contract

### Overall Structure

The STATUS tab layout is unchanged at the top level:
- Full-screen deck map (`EncounterMapDisplay`) fills the section — no change
- Grid background (`#141e1e` lines on `#0a0a0a`) fills the section — no change

Two floating `TerminalPanel` components replace the old four `DashboardPanel`-wrapped cards:

```
┌─────────────────────────────────────────────┐
│  [TerminalPanel: LEFT]    [TerminalPanel: RIGHT] │
│   138px wide                138px wide       │
│   left: 0                   right: 0        │
│   no border on left edge    no border on right edge │
│   chamfer: bottom-right     chamfer: bottom-left   │
│                                              │
│              [Deck Map]                      │
└─────────────────────────────────────────────┘
```

Panels sit `position: absolute; top: 40px (header); bottom: 44px (tab bar)`.

### TerminalPanel: LEFT — Systems

Order of rows, top to bottom:

1. **Panel header** — `SYSTEMS` label (8px, muted, letter-spacing 3px)
2. **HULL row** (hull-row style — larger value, separator border below)
   - Top: label `HULL` (left, text-dim) + value `60 / 60` (right, 14px teal)
   - Bar: 4px tall, teal fill, `box-shadow: 0 0 6px var(--color-teal)`
   - Sub: hull percentage `100%` or condition descriptor (7px, muted, right-aligned)
3. **ARMOR row** (sys-row style — same as other systems below)
   - Top: label `ARMOR` + value `12 / 12` (amber)
   - Bar: 3px, amber fill
   - Info: one-line text (7px, muted)
4. **REACTOR row** (sys-row style — SystemData)
   - Top: label `REACTOR` + status `ONLINE` (colored by status)
   - Bar: 3px, colored by status, width = condition %
   - Info: `Power output nominal` (7px, muted)
5. **LIFE SUPPORT row** (sys-row style)
6. **ENGINES row** (sys-row style)
7. **WEAPONS row** (sys-row style)
8. **COMMS row** (sys-row style)
9. **Footer** — pinned to bottom with `margin-top: auto; border-top: 1px solid var(--color-border-subtle)`
   - `X/5 OPERATIONAL · ⚠ N WARNING` — 7px, muted, letter-spacing 1px
   - Warn count colored `#8b6030` (amber-dark) when > 0

### TerminalPanel: RIGHT — Resources

Order of rows, top to bottom:

1. **Panel header** — `RESOURCES` label
2. **FUEL row** (res-row style)
   - Top: label `FUEL` + value `8 / 12` (amber)
   - Bar: 3px, color by threshold (>50% amber-dim, 25–50% damaged, <25% critical)
   - Sub: remaining percentage (7px, muted)
3. **FOOD row** (res-row style — label `FOOD`, sub: `GALLEY STOCK`)
4. **O2 row** (res-row style — label `O2`, value `94%`, bar width = o2.current/o2.max)
5. **CRYOPODS row** (res-row style — label `CRYOPODS`, value `4 / 8`, sub: `occupied`)
6. **ESCAPE PODS row** (res-row style — label `ESCAPE PODS`, value `2 / 2`)
7. **Footer** — pinned to bottom with separator
   - Label `CREW` (left, 7.5px, muted) + value `7 / 12` (right, 7.5px, text-dim; current count in teal)

### Panel Chamfer (clip-path)

Left panel — chamfer bottom-right corner only:
```css
clip-path: polygon(0 0, 100% 0, 100% calc(100% - 12px), calc(100% - 12px) 100%, 0 100%);
```

Right panel — chamfer bottom-left corner only:
```css
clip-path: polygon(0 0, 100% 0, 100% 100%, 12px 100%, 0 calc(100% - 12px));
```

Chamfer size: 12px (project standard from STYLE_GUIDE.md).

### Scanline Overlay

```css
pointer-events: none;
z-index: 0;
```

## Animation Contract

All animations extend existing patterns in `StatusSection.css`. No new keyframes unless noted.

### Row Stagger-In (D-13)

When STATUS tab loads, rows appear sequentially top-to-bottom. Each row has a CSS class `terminal-row-stagger` with `animation-delay` applied inline.

- Delay increment: 80ms per row
- Row order for delay assignment:
  - LEFT: hull(0ms), armor(80ms), reactor(160ms), life_support(240ms), engines(320ms), weapons(400ms), comms(480ms)
  - RIGHT: fuel(0ms), food(80ms), o2(160ms), cryopods(240ms), escape_pods(320ms)
- Animation: reuse `fade-slide-in` keyframe (already defined in StatusSection.css)
  - `from { opacity: 0; transform: translateY(8px); }` → `to { opacity: 1; transform: translateY(0); }`
  - Duration: 0.4s ease
- After all rows complete (longest delay + 400ms = ~880ms), `staggerComplete` state becomes true and inline delays are removed

### Change-Flash (D-11)

When an SSE update changes a system status, the **entire terminal row** flashes:
- CSS class: `.terminal-row.state-changing`
- Target element: the `.sys-row` div (not the inner content div)
- Keyframe: reuse `flicker` (already defined in StatusSection.css)
- Duration: 400ms, then `state-changing` class removed after 600ms timeout
- Tracks: all 5 systems (life_support, engines, weapons, comms, reactor)

### CRITICAL Pulse

`.sys-row.s-critical` (after stagger completes): reuse `pulse-critical` keyframe.
- Scope: system rows only (not resource rows, not hull/armor)

### OFFLINE Dimming

`.sys-row.s-offline`: `opacity: 0.45; filter: grayscale(0.3)` applied to entire row.

### Condition Bar Fill Transition

`transition: width 0.4s ease` on all `.sys-bar-fill` and `.res-bar-fill` elements.

### Glitch-In (existing — no change)

`.status-map-fill.glitch-enter` — `schematicGlitchIn` keyframe — unchanged. Re-triggered by `revealKey` prop as before.

### Boot Stagger (BridgeView)

The BridgeView `bridge-panel-fade-in` stagger on the STATUS tab itself — unchanged. The new internal row stagger fires after the tab panel is visible.

Source: CONTEXT.md D-11, D-13; StatusSection.css (existing keyframes)

## Component Contract

### New: TerminalPanel

A new component (or internal render function within `StatusSection.tsx`) replacing `DashboardPanel` wrappers inside the status overlays.

**NOT** a general-purpose component. Lives only in `StatusSection.tsx` as a local render helper or a co-located component in the same file.

Props:
```typescript
interface TerminalPanelProps {
  side: 'left' | 'right';       // controls clip-path direction
  children: React.ReactNode;
}
```

Renders:
- `position: absolute` panel with `backdrop-filter: blur(6px)`
- `clip-path` per `side` prop
- `::after` scanline pseudo-element
- Scanline z-index: 0; children z-index: 1 (via `position: relative` on child wrappers)

### SystemRow (internal)

Row structure for system data (reactor, life_support, engines, weapons, comms):
```
<div class="sys-row s-{status} {state-changing?}">
  <div class="sys-row-top">
    <span class="sys-name">{LABEL}</span>
    <span class="sys-status">{STATUS}</span>
  </div>
  <div class="sys-bar-track">
    <div class="sys-bar-fill" style={{ width: `${condition}%` }} />
  </div>
  <div class="sys-info">{info}</div>
</div>
```

### HullRow (internal)

Row structure for hull integrity (hull, armor):
```
<div class="hull-row">
  <div class="hull-top">
    <span class="hull-label">{LABEL}</span>
    <span class="hull-val">{current} / {max}</span>
  </div>
  <div class="hull-bar-track">
    <div class="hull-bar-fill" style={{ width: `${(current/max)*100}%` }} />
  </div>
  <div class="hull-pct">{Math.round((current/max)*100)}%</div>
</div>
```

Hull bar fill: teal. Armor bar fill: amber (color via separate CSS class `.armor-fill`).

### ResourceRow (internal)

Row structure for consumable resources (fuel, food, o2, cryopods, escape_pods):
```
<div class="res-row {low?} {critical?}">
  <div class="res-row-top">
    <span class="res-name">{LABEL}</span>
    <span class="res-val">{value display}</span>
  </div>
  <div class="res-bar-track">
    <div class="res-bar-fill" style={{ width: `${pct}%` }} />
  </div>
  <div class="res-sub">{sub-label}</div>
</div>
```

Resource threshold logic (applied as CSS modifier classes, not inline styles):
- `.res-bar-fill` (default — `>50%`): `var(--color-amber-dim)` `#8b7355`
- `.res-bar-fill.low` (`25–50%`): `#9a6045`
- `.res-bar-fill.critical` (`<25%`): `#8b5555`

Value display per resource:
- fuel: `{current} / {max}` (amber)
- food: `{current} / {max}` (amber)
- o2: `{current}%` (amber, computed as `Math.round(o2.current/o2.max*100)`)
- cryopods: `{occupied} / {total}` (amber)
- escape_pods: `{available} / {total}` (amber)

Sub-label per resource:
- fuel: computed `{Math.round(pct)}% REMAINING`
- food: `GALLEY STOCK`
- o2: `OXYGEN REMAINING`
- cryopods: `OCCUPIED`
- escape_pods: `AVAILABLE`
