<objective>
Backend expansion for Phase 34: harden the tracer's rotate endpoint, make the projection a GM-broadcast setting (set-projection endpoint), and let a deckplan author its initial view (`default_view`), applied exactly once per location change.

Purpose: the tracer (34-01) proved the rotation round trip with minimal validation to stay inside the file budget. This plan completes the server half: strict rotate input handling with the shared `core/encounter_view.py` constants, the projection setter, the authored default view with a per-field normalizer, the location-change reset (D-16 handled with a dedicated store marker), the store/payload default tests, and the schema documentation that CLAUDE.md requires in the same change as the loader.

Output: strict `rotate_view`, `set_projection` + endpoint, `core/encounter_view.py`, `normalize_default_view`, `load_deckplan` returning `default_view`, `api_switch_view` applying it on location change, and updated `docs/schemas/schema-encounters.md`.

Decisions implemented here: D-10 (deck switch keeps the view), D-11 (authored default view; reversibility costly), D-12 (persistence), D-16 (reset on location change only), D-19 (key names `default_view`, `projection`, `rotation_offset`).
</objective>

**Scope rationale (plan-check rev 2, accepted warning):** 14 files is above the 10-file advisory but below the 15-file limit; it absorbs the tracer's hardening plus the D-11 schema change, which CLAUDE.md requires to land with its schema doc in the same task. Moving the store/payload default tests into 34-01 would push 34-01 back toward the limit. Calibrated estimate 55k of a 100k budget.
