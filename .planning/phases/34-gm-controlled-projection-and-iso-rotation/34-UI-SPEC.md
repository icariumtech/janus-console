| Property | Value |

## Locked-Decision Reconciliation

Recorded so the planner does not re-open these from the research file:

- **D-15 supersedes RESEARCH Open Question 1 and Pitfall P10.** Research recommended keeping the authored deck `rotation` as a screen-space `rotate()` under iso. CONTEXT D-15 (post-research, locked) overrides that: under iso the authored rotation becomes a grid-space turn, so every deck gets true 30° axes. Visual consequence: decks with an authored rotation (Somnus, `rotation: 90`) change their iso output from Phase 33. This is intended. Top-down output is unchanged.
- **D-01 supersedes ISO-02** (player-side toggle). REQUIREMENTS.md row must be updated; players have no projection control.
- **D-17 and D-18** are applied in the Layout & Interaction section below.
- **D-19** (YAML key names `default_view.projection` and `default_view.rotation_offset`) is a schema concern. This spec does not define the schema; the schema doc change is a plan task under CLAUDE.md Schema Sync. This spec covers only the visual effect of an authored default (see Authored default view).

Touch target (declared size, not a spacing token): every overlay button in this cluster has `minWidth: 44px` and `minHeight: 44px`. 44 is a multiple of 4.

Exceptions:

- Cluster width of about 194px (see Narrow and tablet viewports) is a derived measurement, not a spacing token. It follows from the 44px minimum width on each rotate button, the 8px gaps, and the `ISO VIEW` label width at 11px with 2px tracking.

## Layout & Interaction Contract

### Control cluster (D-02, D-03, D-04)

- Container: one `div` in the existing `encounter-map__overlays` grid. Style: `gridArea: 'bottom-left'`, `alignSelf: 'end'`, `justifySelf: 'start'`, `display: 'flex'`, `gap: '8px'`. Container `pointerEvents: 'none'`; each button `pointerEvents: 'auto'`.
- Order, left to right: `[ISO VIEW | TOP DOWN]  [⟲]  [⟳]`.
- Shared overlay button style: one style object used by `RESET VIEW` and all three cluster buttons. It carries `background`, `border`, `fontFamily`, `fontSize: '11px'`, `letterSpacing: '2px'`, `padding: '8px 16px'`, `minWidth: '44px'`, `minHeight: '44px'`, `cursor: 'pointer'`. Per-button overrides are `color` and, for the projection button only, `border` colour.
- Rotate buttons render in **both** projections (D-05).
- Mounts that show the cluster: GM tactical map (broadcast mode) and deckplan editor preview (local mode), whenever the grid branch renders.
- Mounts that show no cluster: player terminal, GM side panel, BridgeView thumbnail, StatusSection thumbnail, and the legacy non-grid `MapPreview` branch. Those mounts render the broadcast view read-only.
- `RESET VIEW` keeps its top-left position and its existing pan/zoom gate.

### Rotation semantics (D-05, D-06, D-07, D-09, D-15)

- Each click is one 90° step. `⟲` = −90, `⟳` = +90. The offset wraps 0 → 90 → 180 → 270 → 0.
- Direction: `⟳` turns the whole floor plan clockwise as seen from above, like turning a physical model on the table. `⟲` turns it counter-clockwise.
- The offset is added on top of each deck's authored `rotation`. Offset 0 with no authored rotation is the default view.
- Top-down: output at offset 0 is identical to Phase 33. Rotation is a grid-space turn that commutes with the authored screen rotation.
- Iso: the authored rotation is folded into the grid (D-15). At all four offsets both floor axes stay 30° from horizontal with equal projected length. Rooms stay flat diamonds, not screen-rotated 120°/240° shapes.
- Floor geometry (rooms, hull, details, door glyph axes, background grid) follows the projection. Room labels, token glyphs, and POI icons stay upright and horizontal at every rotation (Phase 33 D-05).
- Hit-testing: a click or drag on a token, POI, door, or room lands on the cell drawn under the pointer at that projection and offset. Verified in the human checkpoint at all eight combinations (2 projections × 4 offsets).

### Motion (D-08, D-14)

| Change | Motion |
|--------|--------|
| Projection change (`ISO VIEW` ↔ `TOP DOWN`) | Cut. No tween. Pan/zoom resets to fit in the same frame. |
| Rotation change (`⟲` / `⟳`) | Fade out 200ms (GSAP `power1.in`) on a wrapper around the map `<svg>`; at opacity 0 set the displayed offset to the broadcast value and reset pan/zoom; fade in 200ms (GSAP `power1.out`). Total about 400ms. |
| Repeated rotate clicks during a fade | Kill the running tween and continue from the current opacity. The snap reads the latest broadcast offset. No step queue. |
| Location change (different map data) | Cut, regardless of whether the offset also changed. |
| Deck switch within the same location (D-10) | No fade and no new reset from this phase. Projection and offset are retained. Deck-switch animation is Phase 35. |
| Mount, SSE reconnect, or any SSE update that leaves projection and offset unchanged (token moves, room toggles, etc.) | No fade, no pan/zoom reset. Compare primitive `projection` and `offset` values only. |
| `prefers-reduced-motion: reduce` | Rotation is a cut: snap offset and reset pan/zoom with no fade. |
| Unmount | Kill the tween in cleanup. |

- The fade wrapper's opacity is driven only by GSAP. Do not set React `style.opacity` on that wrapper (it would fight the tween).

### Pan/zoom reset (D-13)

- Any projection or offset change resets pan/zoom to fit, on the GM map and on players alike. `RESET VIEW` then hides, as it does after any reset today.

### Ownership and sync (D-01, D-03, D-04, D-17)

- **GM tactical map:** the button label and the map reflect the broadcast value only. A click POSTs and waits for the SSE echo. There is no optimistic local update.
- **Player terminal:** no projection control, no rotate control, no orientation badge, no JANUS text cue (D-03, D-14). Pan/zoom and `RESET VIEW` only.
- **Deckplan editor preview:** private local state that never POSTs and never affects the broadcast. Opens top-down at offset 0 (D-17), not at the map's `default_view`. Controls look and behave identically to the GM tactical map.
- **GM side panel and thumbnails:** read-only mirrors of the broadcast view, no buttons.

### Authored default view (D-11, D-12, D-16)

- Loading a different location applies that map's `default_view` (`projection`, `rotation_offset`). Missing `default_view` means top-down, offset 0.
- Re-entering the same location (for example, from BRIDGE) keeps the GM's current view. Only a location slug change applies the default.
- The broadcast view persists across server restart and client reload.

### Mid-drag broadcast change (D-18)

- If a broadcast projection or offset change arrives while a token or POI drag is active, the drag is cancelled. The dragged item returns to its pre-drag cell, no move is applied or written, and no toast is shown.

### Narrow and tablet viewports

- Cluster width at minimum size is about 194px (`ISO VIEW` about 90px + 2 × 44px rotate buttons + 2 × 8px gaps).
- Legend (`LegendPanel`, bottom-right) yields to the cluster: below a 480px viewport width the legend is hidden, never the controls.
- Human checkpoint: verify at 360px width (phone) and about 768px to 1024px (tablet, GM use case).

## Discretion Decisions

Calls made in this contract where CONTEXT.md left the choice open. Each is reversible at the planner or checker's discretion; none requires a user answer.

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Fade is 200ms out + 200ms in, GSAP on a wrapper | Within the 150–250ms-each-way range from CONTEXT; GSAP already a dependency, gives kill/restart semantics. |
| 2 | `prefers-reduced-motion` turns rotation into a cut | No existing convention in `src/`; accessibility default. |
| 3 | Shared overlay button style with 44px minimum, applied to `RESET VIEW` too | Tablet use case. One style object avoids duplicating the chrome (CLAUDE.md: avoid duplication). `RESET VIEW` visual identity is otherwise unchanged. |
| 4 | Cluster order `[ISO VIEW] [⟲] [⟳]` | Keeps the existing projection button in its current slot; rotate pair sits beside it per D-02. |
| 5 | Glyphs `⟲` / `⟳`, text fallback `CCW` / `CW` | Glyphs match the physical-turn metaphor. Font coverage is not verifiable from the repo, so the fallback is pre-declared. |
| 6 | Side panel and thumbnails are read-only mirrors with no buttons | CONTEXT names only the map overlay (D-02); research mount analysis agrees. |
| 7 | Location change is always a cut | A different map is never faded; avoids a fade through the wrong geometry (research P12). |
| 8 | Deck switch in the same location gets no fade and no new reset | D-10 keeps the view; deck-switch animation belongs to Phase 35. |
| 9 | Legend yields below 480px | Controls must always be reachable on a phone. |
| 10 | Tooltips append `(players follow)` | The GM's control now changes what players see; the tooltip says so. |
| 11 | No hover style added | Matches existing overlay buttons; inline styles cannot express hover. |
