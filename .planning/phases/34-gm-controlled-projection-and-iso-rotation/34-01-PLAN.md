<objective>
Tracer plan for Phase 34: prove ONE GM action end to end through every layer the phase will touch, then stop. The GM presses the clockwise rotate button on the tactical map (top-down); the server advances the shared rotation offset, persists it, and broadcasts it on the existing SSE `activeview` event; the GM console's `activeView` carries it; `EncounterMapRenderer` draws the floor plan rotated 90 degrees clockwise through the projection seam.

File budget: the plan touches 14 files and no task touches 10 or more. To stay inside that budget the tracer is deliberately thin and is cut into two legs. Task 1 (`type="tracer"`, 9 files) is the server leg plus the projection seam: HTTP POST, state, disk, SSE payload, and the exact `topDownProjection` call the renderer makes, proven by a Django end-to-end test and a vitest payload-to-pixels test. Task 2 (5 files) is the GM client leg: types, API client, renderer, MapPreview, GM EncounterView. Everything that is breadth rather than the single path is pushed to later plans: strict input hardening and `core/encounter_view.py` (34-02), the shared `viewOrientation.ts` module and normalizers (34-03), the final `viewOrientation` / `viewControl` renderer props and the full control cluster (34-04).

Purpose: surface any architectural dead end (store key allow-list, payload allow-list, projection seam, SSE echo) on the first commit instead of after the other plans are built on top.

Decisions implemented here: D-01 (single GM-owned view, GM map mirrors via SSE), D-06 (clockwise direction), D-07 (offset 0 is identity), D-12 (persists like other encounter state).
</objective>
