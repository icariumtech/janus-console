<objective>
Add decorative detail linework to `deckplan.yaml` and the renderer: consoles, beds, furniture,
machinery blocks and hull greebles, drawn in one fixed blueprint-grade style. Interior details
(entries with a `room:` reference) are reveal-gated by riding inside the room's existing SVG reveal
group; exterior details (no `room:`) are always visible (DET-01, DET-03).

Purpose: the blueprint aesthetic the GM wants, with zero risk of a typo spoiling an unrevealed room.

Output: `DetailEntry` type, `detailNormalizer` (the gating seam), `DetailsLayer` (fixed-style SVG),
interior mounting in `RoomsLayer`, the `patrol_gunboat` detail testbed, and the schema-doc section.

Task ordering here is interface-first (contracts, then wiring, then consumers) — the phase's
end-to-end tracer slice is plan 31-01 Task 1, which already proved the authored-YAML -> normalizer ->
projected-SVG path this plan extends.
</objective>

  <behavior>
    partitionDetails(details, rooms, isGM):
    - entry with no `room` and valid `points` -> lands in `exterior`, for both isGM true and false
    - entry with no `room` and a valid `circle` -> lands in `exterior`
    - entry with `room: 'bridge'` where a room with id `bridge` exists -> lands in `byRoom` under key `bridge`
    - two entries with the same `room` -> both land under that one key, in authored order
    - entry with `room: 'brdige'` (no such room), isGM false -> appears NOWHERE in the result, and console.warn is called naming `brdige`
    - entry with `room: 'brdige'` (no such room), isGM true -> appears in `exterior`, and console.warn is called
    - the same unknown room id referenced by three entries -> console.warn fires once for that id, not three times
    - entry with neither `points` nor `circle` -> dropped, warned, and does not break its siblings
    - entry with `points: [[0,0]]` (single vertex) -> dropped and warned
    - entry with a non-finite coordinate, or `circle.r` of 0 or negative -> dropped and warned
    - `details` undefined or empty -> `{ exterior: [], byRoom: empty Map }`, no warnings
    - the input array and its entries are never mutated
  </behavior>

`partitionDetails(details: DetailEntry[] | undefined | null, rooms: GridRoom[], isGM: boolean): { exterior: DetailEntry[]; byRoom: Map<string, DetailEntry[]> }`.

not read `roomVisibility`. Reveal gating is achieved structurally in Task 2 by mounting `byRoom`
entries inside the room's existing SVG group, so there is exactly one visibility mechanism in the
codebase (D-12/D-13).
