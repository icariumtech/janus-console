<objective>
Deliver per-deck hull geometry end-to-end: a deck in `deckplan.yaml` can declare its own
`hull:` with multiple disjoint polygons and holes, and the renderer draws those polygons
**in addition to** the shared location-level silhouette (HULL-01, HULL-02).

Purpose: unlock pods, nacelles, and detached modules that only exist on one deck, without
migrating a single byte of existing campaign data (D-01 add-alongside).

Output: `hullNormalizer` (the one validation gate), an extended `HullDef` + `NormalizedHull`
type, additive hull rendering with evenodd holes, a bbox that covers every hull polygon,
the `patrol_gunboat` two-deck testbed, and the matching schema-doc rows.
</objective>

(an explicit singular-to-plural transition).

valid forever; `polygons:` is added next to it; both normalize to one internal polygon list
(CONTEXT.md D-01, D-03).

`data/campaign/ship/deckplan.yaml`) that the GM hand-authored. The user explicitly chose no

    - `mergeHulls(undefined, deckHull)` -> deck polygons only

    - `mergeHulls()` / all-null -> `null`

    - one polygon, no holes -> a single `M ... Z` subpath
    - two polygons + one hole -> three `M ... Z` subpaths, projected through the supplied projector
